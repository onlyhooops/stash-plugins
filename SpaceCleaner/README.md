# SpaceCleaner

清理 Stash 媒体目录中**文件/文件夹名称末尾的多余空格**，提供可视化控制面板：先预览、再执行，目标名称冲突时自动跳过，不会覆盖已有文件。

## 功能

- 清理文件夹名称末尾的空格（含 Tab），例如 `测试路径 ` → `测试路径`
- 清理文件扩展名前的空格与名称末尾的空格，例如 `测试文件 .png` → `测试文件.png`、`尾部空格.png  ` → `尾部空格.png`
- 控制面板支持：
  - 选择 Stash 库目录或输入服务器上的绝对路径
  - 单层目录浏览（上一级 / 子文件夹）
  - 递归处理子目录开关
  - 清理对象：文件与文件夹 / 仅文件 / 仅文件夹
  - **预览**：只扫描，不改动磁盘
  - **执行清理**：二次确认后重命名
- 结果统计与明细：扫描项、命中、已重命名、跳过、已屏蔽、错误，并高亮显示被删除的空格（`␣` / `⇥`）
- 支持常见 Unicode 空白字符：不换行空格（U+00A0）、全角空格（U+3000）、零宽空格（U+200B）、BOM 等，不只是 ASCII 空格/Tab
- 清理名称末尾的私用区字符（如 U+F028）、控制/格式/代理字符等不可见噪声；仅处理末尾，名称中间的同名字符保留
- 自动屏蔽 Synology 系统项：`@eaDir`、`#recycle` 目录与 `@SynoEAStream` 文件不扫描、不重命名，目录浏览中也会隐藏
- 安全性：目标名称已存在时跳过；清理后名称为空时跳过；拒绝处理 `/` 及 `/etc`、`/usr` 等系统目录

## 界面入口

- 主界面右上角导航栏的「空格清理」图标
- 或直接访问：`http://<你的 Stash 地址>:9999/space-cleaner`

> 路由使用顶层 `/space-cleaner`，而不是 `/plugin/...`。原因是 Stash 服务端把 `/plugin/{pluginId}/*` 保留给插件静态资源，直接刷新 `/plugin/...` 页面会返回 404；顶层路由可以安全地刷新和收藏。

## 安装

1. 将 `SpaceCleaner` 文件夹放入 Stash 的 `plugins` 目录（与 `config.yml` 同级的 `plugins` 目录）。
2. 在 **设置 → 插件** 中点击 **重载插件**。
3. 确认 `SpaceCleaner` 已启用。
4. 点击顶部导航栏的「空格清理」图标，或访问 `/space-cleaner`。

## 环境要求

- Stash 版本需支持 `runPluginOperation`（v0.25.0 起）
- Stash 进程可执行的 **Python 3**（默认命令为 `python3`）
- 插件以 Stash 进程用户身份运行，因此需要对目标目录有写权限

如果服务器上没有 `python3` 命令，请修改 `SpaceCleaner.yml` 中的 `exec`，改用实际可用的 Python 命令，例如：

```yaml
exec:
  - python
  - "{pluginDir}/space_cleaner.py"
```

## 使用流程

1. 在「1. 选择目录」中输入或浏览选择目录。
2. 按需调整「递归处理子目录」与「清理对象」。
3. 点击 **预览待清理项**，检查列表中的原名称与清理后名称。
4. 确认无误后点击 **执行清理**，在弹窗中再次确认。
5. 查看「清理结果」中的已重命名、跳过与错误明细。

执行操作会同步调用插件，扫描大量文件时页面会显示已用时间；执行期间请保持页面打开。

## 处理规则

| 对象 | 规则 | 示例 |
|------|------|------|
| 文件夹 | 删除名称末尾的空格 / Tab | `测试路径 ` → `测试路径` |
| 文件 | 删除扩展名前与名称末尾的空格 / Tab | `测试文件 .png` → `测试文件.png` |
| 文件 | 没有扩展名时按名称末尾处理 | `文件名 ` → `文件名` |

说明：

- 文件按**最后一个扩展名**切分；`测试文件 .png` 中的空格位于扩展名前，因此会被清理。
- 除 ASCII 空格和 Tab 外，也会处理不换行空格（U+00A0）、全角空格（U+3000）、零宽空格（U+200B）、BOM（U+FEFF）等常见不可见空白字符。
- 名称末尾的私用区字符（Unicode 类别 `Co`，如 U+F028）、控制字符（`Cc`）、格式字符（`Cf`）、孤立代理字符（`Cs`）与各类分隔符（`Zs`/`Zl`/`Zp`）会被视为噪声一并清除，因此 `002  .jpg \uF028` → `002.jpg`。只处理名称末尾，名称中间的同类别字符保持不变。
- 所选目录本身若以空格结尾，也会作为文件夹名称被清理；执行后页面会自动更新为新路径。
- 只修改文件系统名称，**不修改 Stash 数据库**。清理后请到 Stash「任务」页运行一次元数据扫描，让数据库识别新路径。
- 目标名称已存在时跳过（执行前检查），不会主动覆盖。
- 不跟随符号链接目录，避免递归到链接目标。
- `@eaDir`、`#recycle` 目录与 `@SynoEAStream` 文件属于 Synology 系统项，始终跳过；若所选路径本身位于这些目录内，会直接拒绝处理。

## 实现方式

- **外部插件**：`space_cleaner.py` 通过 `raw` 接口接收 JSON 输入，遍历文件系统并输出 JSON 结果。
- **控制面板**：`SpaceCleaner.js` 注册 React 路由与导航入口，通过 GraphQL 的 `runPluginOperation` 同步调用插件，直接拿到预览/清理结果。
- **样式**：`SpaceCleaner.css`，全部限定在 `.space-cleaner-page` / `.sc-*` 命名空间内，不污染 Stash 全局样式。
- 控制面板不使用 `runPluginTask`（异步任务），因为任务输出只写入日志；`runPluginOperation` 可以同步返回结构化结果。
- 页面包裹了 React 错误边界，插件页面异常不会导致整个 Stash UI 白屏。

## 常见问题

**点击预览后提示“插件未返回结果”**

- 确认插件已启用并点击过 **重载插件**。
- 确认 Stash 进程能找到 `python3`，可先在服务器上执行 `python3 --version`。
- 查看 Stash 日志中是否有 `Plugin / SpaceCleaner` 相关错误。

**执行时出现 Permission denied**

- Stash 进程用户对目标目录没有写权限；请调整目录所有者/权限，或改用有权限的目录。

**清理后 Stash 中显示文件丢失**

- 文件系统名称已变更，但 Stash 数据库仍保存旧路径；请运行一次元数据扫描。
